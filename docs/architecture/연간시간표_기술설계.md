# 연간 시간표 나이스 자동입력 — 기술 설계

상태: 설계 기준 확정, 구현 전  
최종 갱신: 2026-08-18  
관련 문서: [개발 로드맵](../roadmap/연간시간표_자동입력_로드맵.md) · [실기기 검증 절차](../maintenance/연간시간표_실기기검증.md)

이 문서는 연간 시간표 계획 파일을 읽어 4세대 나이스의 「학급시간표관리」에 입력하는 기능의 구현 기준이다. 구현자가 바뀌어도 입력 해석, 사용자 매핑, 창의적 체험활동 처리, 나이스 조작의 안전 원칙이 달라지지 않도록 결정 사항과 실측 사실을 한곳에 고정한다.

---

## 1. 목표와 범위

### 목표

1. 사용자가 연간 시간표 계획 파일(PDF/HWP/HWPX)을 올리면 날짜별·교시별 수업을 구조화한다.
2. 나이스에서 현재 학교·사용자·학년도·학기·학년·반에 실제로 제공되는 과목과 교사 목록을 읽는다.
3. 원본의 짧은 표기(국, 수, 사, 과, 창 등)를 실제 나이스 항목에 연결한다.
4. 같은 과목에 교사가 여러 명이면 전체 기본값뿐 아니라 요일·교시·특정 날짜 단위로 교사를 정할 수 있게 한다.
5. 창의적 체험활동은 별도 창체 계획을 함께 분석해 자율·자치활동, 동아리활동, 진로활동으로 나눈다.
6. 입력 전에 전체 계획을 미리 보여 주고, 미해결·충돌·기존 값 덮어쓰기 위험을 모두 해소한 뒤 실행한다.
7. 주 단위 검증과 체크포인트를 이용해 중단·실패·재실행에도 중복 또는 오입력을 막는다.

### 이번 설계에서 제외하는 것

- 나이스 로그인과 인증서 선택 자동화
- 과목명·교사명·계정 ID의 하드코딩
- AI가 나이스의 최종 과목 또는 교사를 임의로 결정하는 동작
- 확인되지 않은 기존 시간표를 자동으로 덮어쓰는 동작
- 행사처리, 결보강처리, 수업삭제 같은 특수 명령의 자동 실행

## 2. 절대 지켜야 할 불변 조건

아래 조건은 편의를 위해 완화하지 않는다.

1. **런타임 목록이 최종 권위다.** 과목·교사·창체 항목은 해당 사용자의 나이스 메뉴에서 매번 읽는다.
2. **원본 해석과 나이스 매핑을 분리한다.** AI 결과는 “무슨 수업인지”까지만 제안하고, 실제 메뉴 항목 선택은 런타임 목록과 사용자 확인으로 확정한다.
3. **셀 주소는 실제 날짜 + 교시다.** 주차 번호나 화면 열 순서만으로 셀을 식별하지 않는다.
4. **동적 UUID를 저장하지 않는다.** 메뉴를 다시 열 때 바뀌는 uuid-* 값은 셀렉터나 매핑 키로 사용하지 않는다.
5. **복수 교사를 첫 항목으로 자동 선택하지 않는다.** 후보가 둘 이상이면 사용자가 정했거나 더 구체적인 규칙이 있을 때만 확정한다.
6. **창은 미해결 표기다.** 창 또는 (창)을 자율·자치활동 등 하나로 임의 치환하지 않는다.
7. **특수 명령은 수업 후보가 아니다.** 행사처리, 수업삭제, 교사추가 등은 자동 매핑 후보에서 제거한다.
8. **기존 값과 목표가 다르면 기본적으로 중단한다.** 사용자가 미리보기에서 해당 충돌의 덮어쓰기를 명시적으로 허용해야 한다.
9. **입력 후 다시 읽어 검증한다.** 클릭 성공만으로 입력 성공을 판정하지 않는다.
10. **개인정보를 저장소에 남기지 않는다.** 학교명, 교사명, 계정 ID, 로컬 사용자 경로는 문서·테스트·진단 샘플에서 가린다.

## 3. 전체 파이프라인

~~~text
[연간 시간표 파일]     [선택: 창체 계획 파일]
          │                      │
          └──── 문서 추출 ───────┘
                     │
              AI 구조화 제안
                     │
         결정론적 정규화·검증·중복 제거
                     │
           원본 시간표 중간 모델
                     │
     나이스 읽기 전용 진단·런타임 목록 수집
                     │
       사용자 과목·교사·창체 매핑 및 예외 규칙
                     │
       날짜+교시 기준 실행 계획과 전체 미리보기
                     │
        주 단위 입력 → 셀 재검증 → 저장 확인
                     │
          재조회 검증·체크포인트·결과 보고
~~~

AI 호출 뒤에는 반드시 순수 C# 검증 단계를 둔다. 날짜 범위, 요일, 교시, 중복, 수업 총량, 창체 분류, 미매핑을 코드로 검사해야 하며 AI 응답을 그대로 브라우저 조작에 넘기지 않는다.

## 4. 기존 계층과 통합 위치

의존 방향은 기존과 같이 안쪽으로만 유지한다.

~~~text
App → Automation ─┐
App → Generator ──┼→ Core
App → Excel ──────┘
~~~

### Core

권장 위치: src/NeisAutoFill.Core/Timetable/

- 날짜·교시 주소
- 원본 토큰과 정규화 결과
- 나이스 메뉴 옵션의 타입
- 매핑 규칙과 우선순위
- 창체 이벤트와 중복 제거 결과
- 실행 계획, 검증 문제, 충돌, 결과
- 브라우저 없이 테스트 가능한 계획 생성기

### Generator

재사용:

- PlanFileExtractor의 PDF/HWP/HWPX 추출 경로
- HWP의 한컴 COM → 임시 PDF 변환
- HWPX 표 경계를 남기는 텍스트 평탄화
- GAS 요청·진행률·취소 패턴

새로 분리할 것:

- 평가계획용 스키마와 섞지 않은 시간표 전용 AI 요청
- 연간 시간표 목록 추출과 창체 계획 추출
- 원본 위치·신뢰도·경고를 보존하는 응답 DTO

### Automation

재사용:

- 사용자 로그인 Edge에 CDP로 연결하는 NeisEngine 세션
- CLX 컨트롤 탐색과 reveal 방식
- DomInspector의 읽기 전용 진단 기반
- BatchUploadRunner의 “검증 성공 후 저장, 실패 시 중단” 개념

새로 필요한 것:

- Timetable 화면 감지와 이동
- 주차·실제 날짜·셀 상태 읽기
- 열린 컨텍스트 메뉴 안에서만 옵션 목록 수집
- 실제 스크롤 컨테이너를 이용한 대상 선택
- 셀별 입력·재검증과 주 단위 저장·재조회

### App

재사용:

- MatchPreviewWindow/ViewModel의 추천, 입력 안 함, 중복 선택 방지 UX
- BatchUploadFlow의 단계 표시와 결과 대시보드
- NeisSessionController의 연결·준비 상태 관리

새로 필요한 것:

- 시간표 파일 가져오기 화면
- 원본 인식 검토 표
- 과목·교사·창체 매핑 화면
- 날짜별 예외 규칙 편집
- 전체 연간 미리보기와 충돌 필터
- 주 단위 실행 진행률·중단·재개 화면

현재 평가 입력의 매핑 UI를 그대로 복사하지 않는다. 시간표는 같은 원본 과목이 여러 교사에게 연결될 수 있으므로 일대일 매핑만으로는 부족하다.

## 5. 권장 중간 모델

실제 이름은 구현 과정에서 조정할 수 있지만 책임은 아래처럼 분리한다.

### 입력 모델

**TimetableSourcePackage**

- 연간 시간표 원본 정보
- 선택적 창체 계획 원본 정보
- 학년도·학기·학년·반 힌트
- 추출 경고 목록

**TimetableSourceLesson**

- 실제 날짜
- 요일
- 교시
- 원본 표기
- 정규화 표기
- 원본 페이지·표·행·열 등 추적 정보
- AI 신뢰도와 경고

**CreativeActivityEvent**

- 날짜 또는 날짜 범위
- 선택적 교시
- 자율·자치/동아리/진로/미분류
- 활동명
- 전체 계획 또는 세부 계획 출처
- 중복 묶음 ID와 출처 목록

### 나이스 카탈로그 모델

**NeisTimetableOption**

- 종류: 일반 수업 / 창체 / 특수 명령 / 취소 / 알 수 없음
- 화면 원문
- 과목명
- 교사 표시명
- 교사 계정 식별자
- 창체 세부 종류
- 현재 카탈로그 안에서만 쓰는 안정 키

안정 키는 화면 UUID가 아니라 정규화된 종류·과목·교사·계정 값으로 만든다. 개인정보 원문을 로그에 노출하지 않도록 저장 시 해시를 사용할 수 있다.

**TimetableCatalogSnapshot**

- 나이스 호스트·교육청
- 학교/사용자 범위 식별값의 해시
- 학년도·학기·학년·반
- 읽은 시각
- 할당 가능한 옵션 목록
- 특수 명령 목록
- 정렬에 독립적인 카탈로그 지문

### 매핑 모델

**TimetableMappingRule**

- 원본 토큰
- 대상 옵션 안정 키
- 적용 범위
- 사용자가 직접 확정했는지
- 마지막 카탈로그 지문

적용 범위 우선순위:

1. 특정 날짜 + 교시
2. 요일 + 교시
3. 요일
4. 원본 토큰 전체 기본값

같은 우선순위 규칙이 둘 이상 맞으면 첫 항목을 고르지 않고 충돌로 처리한다.

예:

- 창의 기본값은 미설정
- 월요일 3교시 창 → 자율·자치활동 / 담임
- 수요일 2교시 창 → 진로활동 / 보건 담당 교사
- 9월 16일 수요일 2교시는 별도 행사 때문에 다른 교사로 날짜 예외 설정

### 실행 모델

**TimetableAssignment**

- 날짜 + 교시
- 원본 수업
- 확정 대상 옵션
- 결정에 사용한 매핑 규칙
- 현재 나이스 셀 값
- 실행 분류

실행 분류는 최소 다음을 구분한다.

- 입력 예정
- 이미 일치
- 빈 수업/수업 없음
- 원본 미해결
- 매핑 미해결
- 복수 교사 충돌
- 창체 미분류
- 기존 값 충돌
- 나이스 날짜 범위 밖
- 휴업일 또는 메뉴 열기 불가

## 6. 원본 파일 인식

### 지원 입력

- 연간 시간표: PDF, HWP, HWPX
- 선택적 창체 계획: PDF, HWP, HWPX
- 같은 내용의 여러 형식을 동시에 올리는 기능은 필요하지 않다. 한 파일을 기준 원본으로 선택한다.

### AI 응답 최소 스키마

~~~json
{
  "schoolYear": 2026,
  "semester": 2,
  "lessons": [
    {
      "date": "2026-08-24",
      "dayOfWeek": "MONDAY",
      "period": 1,
      "sourceToken": "국",
      "sourceLocation": "p.2/table-1/r4/c3",
      "confidence": 0.98,
      "warnings": []
    }
  ],
  "warnings": []
}
~~~

창체 계획은 별도 events 배열로 받고 activityKind를 AUTONOMY, CLUB, CAREER, UNRESOLVED 중 하나로 제한한다.

### 결정론적 후처리

- 날짜 파싱 실패는 오류
- 교시는 양의 정수여야 함
- 문서의 요일과 실제 날짜 요일이 다르면 경고
- 동일 날짜·교시가 두 수업으로 나오면 충돌
- 빈칸, 휴업, 행사 표기는 수업 토큰과 분리
- 학기 범위를 벗어난 날짜는 경고
- 원본 위치가 없는 AI 행은 검토 대상으로 표시

AI는 불확실한 셀을 빈칸으로 숨기지 말고 경고와 함께 반환해야 한다.

## 7. 과목 토큰 정규화

한 글자 별칭은 나이스 값으로 바로 바꾸는 것이 아니라 “표준 원본 의미”로만 확장한다.

| 원본 | 표준 의미 |
|---|---|
| 국 | 국어 |
| 수 | 수학 |
| 사 | 사회 |
| 과 | 과학 |
| 도 | 도덕 |
| 실 | 실과 |
| 체 | 체육 |
| 음 | 음악 |
| 미 | 미술 |
| 영 | 영어 |
| 창, 창체, (창) | 창의적 체험활동 미분류 |

정규화는 유니코드 호환 정규화, 양끝 괄호, 불필요한 공백, 가운뎃점 차이를 처리한다. 사전에 없는 값은 버리지 않고 그대로 사용자 매핑 대상으로 남긴다. 학교별 특색과목처럼 임의 과목명이 존재할 수 있기 때문이다.

자동 제안 기준:

1. 원문 정확 일치
2. 표준 의미 정확 일치
3. 공백·가운뎃점 정규화 일치
4. 유사도 추천

1~3도 대상 옵션이 하나일 때만 자동 확정할 수 있다. 같은 과목에 교사가 둘 이상이면 전부 후보로 보여 주고 사용자 결정이 필요하다.

## 8. 창의적 체험활동 병합과 중복 제거

### 기본 원칙

- 연간 시간표의 창은 세부 종류를 알 수 없는 자리 표시자다.
- 창체 계획이 있으면 날짜·활동명·세부 종류를 이용해 해당 셀을 해석한다.
- 창체 계획이 없어도 사용자가 셀별 또는 반복 규칙으로 직접 정할 수 있다.
- 미분류 창이 한 건이라도 남으면 자동 실행을 막는다.

### 전체 계획과 세부 계획이 함께 있는 경우

같은 활동을 두 번 세지 않도록 다음 순서로 묶는다.

1. 날짜 또는 날짜 범위가 겹치는지 확인
2. 정규화한 활동명과 세부 종류 비교
3. 교시 정보가 있으면 일치 여부 비교
4. 같은 활동으로 판단되면 세부 계획 행을 대표로 사용
5. 전체 계획 행은 삭제하지 않고 대표 행의 출처 목록에 병합

자동 병합이 불가능한 경우:

- 날짜는 같지만 세부 종류가 다름
- 같은 날짜·활동인데 교시가 충돌
- 전체 계획의 시수와 세부 계획 합계가 맞지 않음
- 활동명이 지나치게 일반적이라 같은 활동인지 판단 불가

이 경우 하나를 임의 선택하지 않고 “창체 중복/충돌 검토” 목록으로 보낸다.

권장 중복 키:

~~~text
정확 키 = 날짜 + 교시 + 창체종류 + 정규화 활동명
느슨한 키 = 날짜 + 창체종류 + 정규화 활동명
~~~

느슨한 키 일치는 자동 삭제가 아니라 병합 후보 제안에만 사용한다.

## 10. 런타임 카탈로그 수집 전략

1. 현재 화면이 정확한 학급시간표관리인지 확인한다.
2. 학년도·학기·학년·반을 읽고 사용자 목표와 비교한다.
3. 입력 가능한 대표 빈 셀을 찾는다.
4. 우클릭 후 새로 열린 오버레이 내부로 탐색 범위를 제한한다.
5. 메뉴의 모든 버튼을 읽고 할당 가능한 수업과 특수 명령으로 타입 분류한다.
6. 보이지 않는 항목은 메뉴 스크롤 요소를 움직여 실제 선택 가능성도 검증한다.
7. 메뉴를 취소로 닫아 화면 데이터를 변경하지 않는다.
8. 할당 가능 항목의 정렬 독립 카탈로그 지문을 만든다.

대표 셀이 없거나 모든 날이 수업 없음이면 카탈로그를 읽을 수 없다는 안내를 하고 다른 주차를 사용자가 고르게 한다. 특수 명령을 눌러 메뉴를 닫는 방식은 금지한다.

메뉴 문자열은 오른쪽의 두 괄호 그룹을 구조적으로 파싱한다.

~~~text
과목(교사명(계정ID))
~~~

단순히 첫 괄호에서 자르면 과목명 또는 명령 안의 괄호 때문에 오분류할 수 있다. 명령 텍스트를 먼저 제외하고, 마지막 바깥 괄호와 그 안의 마지막 계정 괄호를 균형 있게 해석한다.

## 12. 실행 계획과 안전한 입력

### 사전 검증

실행 전 읽기 전용으로 전체 목표를 분류한다.

- 입력 예정
- 이미 일치
- 기존 값 충돌
- 미매핑
- 창체 미분류
- 메뉴 열기 불가
- 휴업일
- 학기 범위 밖
- 중복 목표

막힌 건이 하나라도 있으면 기본 실행은 비활성화한다. 사용자가 “충돌만 제외하고 진행” 같은 범위를 명시적으로 선택할 수는 있지만 제외 목록을 결과에 남긴다.

### 셀 입력

1. 실제 날짜가 포함된 주차로 이동
2. CLX 데이터와 헤더에서 날짜 열 확인
3. 교시 행 확인
4. 현재 값 다시 읽기
5. 이미 목표와 같으면 건너뜀
6. 기존 다른 값이면 허용 규칙 없이는 중단
7. 우클릭해 열린 메뉴 범위 확인
8. 대상 안정 키와 일치하는 현재 메뉴 항목 찾기
9. 필요하면 메뉴 자체를 스크롤
10. 항목 클릭
11. 셀을 다시 읽어 과목·교사 일치 확인
12. 실패 시 한 번만 재시도하고 계속 실패하면 해당 주 저장 금지

### 저장

초기 구현은 “입력 후 사용자 수동 저장” 모드부터 완성한다. 자동 저장은 별도 단계에서 다음 조건을 모두 만족할 때만 제공한다.

- 사용자가 배치 자동 저장에 명시적으로 동의
- 해당 주의 목표 셀이 전부 재검증 성공
- 예상하지 않은 기존 값 변경이 없음
- 저장 확인 대화상자의 종류가 허용 목록과 일치
- 저장 후 재조회 결과가 계획과 일치

대화상자에 확인 버튼이 있다는 이유만으로 누르지 않는다. 제목과 본문을 타입으로 판별하고 알 수 없는 대화상자는 사용자에게 넘긴다.

### 중단과 재개

체크포인트는 주 단위로만 완료 처리한다.

- 계획 ID와 원본 파일 해시
- 카탈로그 지문
- 주 시작일
- 저장 전 스냅샷 요약
- 목표 셀 수와 검증 결과
- 저장·재조회 성공 여부

재개할 때는 체크포인트를 믿고 건너뛰지 않고 현재 나이스 값을 다시 읽어 일치 여부를 확인한다.

## 17. 구현자가 가장 먼저 할 일

1. Core에 날짜·교시, 원본 토큰, 메뉴 옵션, 매핑 규칙, 실행 분류 모델을 만든다.
2. 브라우저 없이 메뉴 문자열 파서·토큰 정규화·규칙 우선순위를 테스트한다.
3. 그 다음에만 문서 AI 스키마와 시간표 전용 읽기 진단을 구현한다.
4. 입력 기능보다 전체 미리보기와 차단 조건을 먼저 완성한다.
5. 자동 저장은 단일 셀·한 주 미저장 입력과 재검증이 실기기에서 안정화된 뒤 시작한다.

단계별 작업과 완료 기준은 로드맵 문서를 따른다.
