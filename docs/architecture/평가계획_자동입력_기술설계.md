# 평가계획 자동입력 — 기술설계

작성: 2026-08-21 · 상태: 설계(구현 전)
관련: [나이스 화면 지도](../maintenance/평가계획_나이스_화면지도.md) · [로드맵](../roadmap/평가계획_자동입력_로드맵.md)
바탕: [연간시간표 기술설계](연간시간표_기술설계.md) — 구조와 원칙을 그대로 물려받는다

## 1. 무엇을 만드나

학교에서 받은 **평가계획 문서(한글)** 를 읽어 나이스 **평가계획(안)관리**에 넣는다.

```
평가계획.hwp  →  파싱  →  교사 확인·보정  →  나이스 입력  →  저장·검증
```

지금 평가 탭이 하는 일(교과평가 등급, 교과학습발달상황)에 <b>세 번째 축</b>으로 붙는다.

넣어야 하는 것은 두 겹이다.

| 겹 | 내용 | 나이스 위치 |
|---|---|---|
| ① 성취기준 | 영역명 · 성취기준 · 평가요소 | 1단계 성취기준관리 |
| ② 평가기준 | 단계 수 + 단계마다 (평가단계, 평가결과) | 2단계 성취기준(평가기준)관리 |

그리고 ① 앞에 <b>영역명 등록</b>이 먼저다(영역명은 콤보라 미리 등록된 것만 고를 수 있다).

## 2. 실행 순서 — 세 걸음

```
0. 영역명 등록      교과마다 [영역명관리] 에 영역명들을 넣는다
1. 성취기준 입력    영역명 고르고 성취기준·평가요소를 넣는다
2. 평가기준 입력    행을 고르고 단계 수를 정한 뒤 단계·결과를 넣는다
```

각 걸음 끝에 저장하고 <b>재조회로 확인</b>한다. 시간표에서 세운 원칙 그대로 —
"클릭 성공은 입력 성공이 아니다".

## 3. 두 갈래 입력 경로

| | 엑셀 일괄업로드 | 화면 직접 입력 |
|---|---|---|
| 쓸 수 있는 곳 | ① 성취기준만 | ①② 둘 다 |
| 속도 | 교과당 한 번 | 칸마다 클릭 |
| 위험 | 낮음 | 그리드 편집 규칙이 까다롭다 |
| 되돌리기 | 추가만 됨(중복 위험) | 행 단위 삭제 |

**②(평가기준)에는 안전한 일괄 경로가 없다.** [전과목일괄입력]은 전 교과에 같은 값을 밀어 넣고
기존 것을 지운다 — 영역마다 평가결과가 다른 우리 용도에 맞지 않는다.

> 그러므로 <b>① 은 엑셀, ② 는 화면 입력</b>을 기본으로 삼는다.
> ① 도 화면 입력 경로를 함께 만들어 둔다 — 엑셀 양식이 교육청마다 다를 수 있고,
> 두 번 올리면 중복되는 문제가 있어 "이미 있는 것은 건너뛴다"를 우리가 판단해야 하기 때문이다.

## 4. 계층 (기존 5계층 그대로)

```
Core        평가계획 도메인 · 문서 파싱 · 계획 수립     (브라우저·엑셀 모름)
Excel       나이스 업로드용 통합문서 생성
Automation  나이스 화면 조작 (Playwright)
Generator   한글·PDF 에서 글자와 좌표 뽑기            (이미 있음)
App         평가 탭 UI
```

### Core

```
EvalPlanDocument        문서 한 벌
 └ EvalSubjectPlan      교과 하나
    └ EvalArea          영역 하나 (영역명)
       └ EvalStandard   성취기준 하나
          ├ 성취기준 / 평가요소
          └ EvalCriterion[]  (평가단계, 평가결과)
```

- `EvalLevelScale` — 평가기준 <b>줄 수를 세어</b> 단계 수를 정한다.
  문서에 "3단계"라고 적혀 있지 않다. `잘함·보통·노력요함` 이면 3단계다.
  나이스가 받는 값은 `2/3/4/5/7단계` 뿐이므로, 그 밖의 수가 나오면 <b>막고 사람에게 묻는다</b>.
- `EvalPlanDocumentParser` — 좌표 기반 표 복원(§5).
- `EvalPlanBuilder` — 문서 + 나이스 현재 상태 → 칸별 실행 계획.
  시간표의 `TimetablePlanBuilder` 와 같은 꼴로 만든다: 미리 전부 분류하고,
  막힌 것이 하나라도 있으면 실행을 잠근다.

### Automation

| 클래스 | 하는 일 |
|---|---|
| `EvalScreenReader` | 화면 판별 · 조회 조건 읽기/고르기 · 그리드 읽기 |
| `EvalAreaWriter` | [영역명관리] 대화상자에서 영역명 등록 |
| `EvalStandardWriter` | 성취기준 행 추가·입력 (또는 엑셀 업로드) |
| `EvalCriteriaWriter` | 단계 수 선택 + 평가단계·평가결과 입력 |
| `EvalPlanSaver` | 두 단계 저장 상자 처리 |

`EvalPlanSaver` 는 `TimetableSaver` 와 <b>같은 문제를 푼다</b> — 확인을 두 번 눌러야 하고
그 사이에 아무 상자도 없는 구간이 있다. <b>기존 코드를 공유하도록 뽑아낸다.</b>

### 그리드 편집기 (핵심 부품)

화면 지도 §5 의 규칙을 한 곳에 가둔다.

```csharp
// 다음에 채울 칸을 눌러 가며 연쇄로 채우고, 마지막은 [저장]이 확정한다.
await grid.FillChainAsync(new[] {
    (row: 0, col: 0, "잘함"),
    (row: 0, col: 1, "…"),
    …
});
```

- 확정은 <b>다음 칸 클릭</b>으로만 한다 (Enter·Tab·Escape·바깥 클릭은 안 먹는다)
- 눌린 칸은 비워지므로 <b>순서가 곧 안전장치</b>다
- 다 넣은 뒤 <b>반드시 다시 읽어</b> 대조한다 (첫 접촉 때 편집모드 진입이 실패한 적이 있다)

## 5. 문서 파싱

실측(2026학년도 5학년 1학기 평가계획.hwp): **7쪽, 전부 표**. 열 구성:

```
성취기준코드 │ 영역 │ 성취기준 │ 평가요소 │ 평가기준(잘함·보통·노력요함) │ 평가시기 │ 평가방법
```

글자만 뽑으면 <b>열이 뒤섞인다</b> — 같은 Y 에 있는 다른 열 글자가 한 줄로 붙는다:

```
자료를선별수행평가
듣하여핵심정(구술평가)[프로젝트학습]
```

그래서 시간표에서 쓴 방식을 그대로 쓴다: `Generator` 가 뽑아 준 **글자별 X 좌표**로
열 경계를 찾고, 셀 단위로 되살린 뒤 읽는다. 이미 `DocumentLayout`·`TextGlyph` 가 있다.

주의할 점:

- **평가단계는 말로 적혀 있다.** `잘함/보통/노력요함` → 세어서 3단계.
  학교마다 `상/중/하`, `매우잘함/…` 처럼 다를 수 있으니 <b>이름을 고정하지 않는다.</b>
- 한 성취기준의 평가기준 문장이 여러 줄에 걸친다 → 셀 안에서 이어 붙인다.
- 평가시기·평가방법은 나이스 이 화면에 넣는 자리가 없다 → 읽되 쓰지 않는다.
- 한컴 COM(`HwpToPdf`)이 <b>가끔 멈춘다.</b> 이미 알려진 문제다 —
  파싱 전에 남은 `Hwp.exe` 를 정리하고, 실패하면 사용자에게 PDF 저장을 안내한다.

## 6. 결정

| ID | 결정 | 왜 |
|---|---|---|
| E-001 | 영역명 등록 → 성취기준 → 평가기준 <b>순서를 강제</b>한다 | 영역명이 없으면 성취기준을 넣을 수 없다 |
| E-002 | 단계 수는 <b>문서에서 세어</b> 정한다. 2/3/4/5/7 이 아니면 멈춘다 | 문서에 숫자로 적혀 있지 않다 |
| E-003 | [전과목일괄입력]은 <b>쓰지 않는다</b> | 기존 평가기준을 지우고 전 교과에 같은 값을 넣는다 |
| E-004 | 엑셀 일괄업로드는 <b>이미 있는 성취기준을 우리가 걸러</b> 올린다 | 나이스가 덮어쓰지 않고 추가만 한다 → 중복 |
| E-005 | 저장 로직은 시간표와 <b>공유</b>한다 | 두 단계 상자 구조가 같다 |
| E-006 | 넣은 뒤 <b>재조회로 대조</b>해야 완료로 본다 | 그리드 편집이 조용히 실패한다 |
| E-007 | 되돌릴 수 없는 삭제는 <b>하지 않는다</b> | 지우기는 사람이 화면에서 한다 |

## 7. 열어 둔 것

- **샘플 엑셀 양식의 열 구성** — [샘플엑셀다운로드]를 눌렀지만 파일을 찾지 못했다.
  사용자가 `docs/eval` 에 넣어 주기로 했다. 그때 `EvalPlanWorkbookWriter` 를 확정한다.
- **엑셀업로드가 영역명을 자동으로 만들어 주는지** — 아니면 미리 등록해야 하는지 미확인.
  만들어 준다면 걸음 0 을 건너뛸 수 있다.
- 교과 목록을 어디서 얻을지(조회 조건 콤보의 교과 목록 = 개설 교과로 보인다).
