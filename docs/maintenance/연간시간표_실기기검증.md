# 연간 시간표 자동입력 — 나이스 실기기 검증 절차

상태: 최초 실측 기준 작성  
최종 갱신: 2026-08-18  
관련 문서: [기술 설계](../architecture/연간시간표_기술설계.md) · [개발 로드맵](../roadmap/연간시간표_자동입력_로드맵.md)

이 문서는 나이스 화면을 실제로 확인하거나 자동화 어댑터를 변경할 때 따르는 안전 절차다. 화면 개편, 교육청별 차이, 메뉴 구조 변경에 대응할 수 있도록 “무엇을 확인했고 무엇은 아직 가정인지”를 기록한다.

---

## 1. 원칙

1. 로그인과 인증서는 사용자가 직접 처리한다.
2. 읽기 전용 진단을 쓰기 시험보다 먼저 완료한다.
3. 실제 교사명·계정 ID·학교명·사용자 경로를 저장소에 커밋하지 않는다.
4. 테스트는 빈 셀 한 건에서 시작하고, 저장은 별도 승인 단계에서만 한다.
5. 수업 후보가 아닌 명령은 절대 시험 선택하지 않는다.
6. 알 수 없는 확인창은 자동 승인하지 않는다.
7. 클릭 성공이 아니라 셀 재읽기와 저장 후 재조회로 성공을 판정한다.
8. 한 단계가 실패하면 더 넓은 범위 시험으로 넘어가지 않는다.

---

## 2. 시험 전 준비

### 사용자 확인

- [ ] 시험용 학년도·학기·학년·반을 사용자가 확인
- [ ] 변경해도 되는 빈 날짜·교시를 사용자가 지정
- [ ] 저장하지 않는 시험인지 저장 시험인지 명확히 구분
- [ ] 저장 시험이면 원래 값과 복구 방법을 기록
- [ ] 세션 만료까지 남은 시간이 충분한지 확인
- [ ] 실제 업무 시간표에 영향이 없는 범위인지 확인

### 프로그램 확인

- [ ] 현재 브랜치와 커밋 기록
- [ ] 전체 dotnet test 통과
- [ ] 시간표 진단 모드가 쓰기 동작을 하지 않는지 코드 검토
- [ ] 로깅 마스킹 활성화
- [ ] 진단 파일 저장 경로 확인
- [ ] 자동 저장 기본값 OFF
- [ ] 취소 토큰과 긴급 중단 동작 확인

### 자료 비식별화

원본 진단 파일을 공유하거나 커밋하기 전에 다음 값을 치환한다.

| 실제 값 | 치환 예 |
|---|---|
| 학교명 | SCHOOL_A |
| 교사명 | 교사A, 교사B |
| 로그인 ID | user-a |
| 교사 계정 ID | account-a |
| 사용자 폴더 | C:\Users\USER |
| 학생 정보 | 전부 삭제 |

단순 화면 블러만으로 끝내지 않는다. DOM 텍스트, JSON, 툴팁, aria-label, 파일명에도 실제 값이 남을 수 있다.

## 3. 읽기 전용 진단 순서

### V1. 화면 식별

- [ ] 현재 URL이 교육청 나이스 호스트인지 확인
- [ ] 로그인 상태 확인
- [ ] 학급담임 → 시간표관리 → 학급시간표관리로 이동
- [ ] 화면 제목과 앱 ID 수집
- [ ] 학년도·학기·학년·반 값 수집
- [ ] 목표 화면이 아니면 Ready로 판정하지 않음

기록:

~~~text
검증일:
교육청/호스트(마스킹 가능):
앱 ID:
화면 제목:
학년도/학기/학년/반:
검증자:
~~~

### V2. CLX 컨트롤 목록

- [ ] 실행 중인 앱 인스턴스 목록
- [ ] 모든 grid 컨트롤 ID
- [ ] 각 grid의 논리 열 수·데이터 행 수
- [ ] 컬럼명과 바인딩 필드
- [ ] viewing start/end, reveal 가능 여부
- [ ] DOM aria 행·열 수와 CLX 논리 수 차이

시간표 그리드는 ID만 믿지 않고 다음 구조도 함께 확인한다.

- 1~8교시 행
- 월~일 날짜 열
- 날짜 필드
- 셀 출력/정보 필드

### V3. 주차와 실제 날짜

- [ ] 주차 목록의 표시 범위 수집
- [ ] 선택 주의 월~일 헤더 날짜 수집
- [ ] CLX 행의 요일별 Ymd 값 수집
- [ ] 주차 표시 범위, 헤더 날짜, Ymd가 같은지 비교
- [ ] 토요일·일요일·휴업일 표시 확인

주차 번호를 영속 셀 주소로 쓰지 않는다. 한 주의 시작일은 탐색용이고 최종 셀 주소는 실제 날짜+교시다.

### V4. 셀 읽기

대표 셀마다 다음을 읽는다.

- [ ] 빈 평일 셀
- [ ] 값이 있는 셀
- [ ] 토요일/일요일 셀
- [ ] 수업 없는 날
- [ ] 1교시와 마지막 교시

기록 필드:

~~~text
날짜:
교시:
CLX 원시 값(비식별):
화면 표시:
우클릭 가능 여부:
툴팁/상태:
~~~

### V5. 컨텍스트 메뉴

빈 입력 가능 셀 한 곳에서만 실행한다.

- [ ] 우클릭 전 오버레이 수 기록
- [ ] 우클릭 후 새 오버레이 식별
- [ ] 메뉴 루트와 스크롤 요소 식별
- [ ] clientHeight, scrollHeight, scrollTop 기록
- [ ] 모든 버튼 텍스트를 비식별화해 수집
- [ ] 할당 가능한 수업과 특수 명령 분류
- [ ] 같은 과목에 여러 교사가 있는지 확인
- [ ] 창체 세 종류 확인
- [ ] DOM 항목 수와 스크롤 전후 항목 ID/텍스트 비교
- [ ] 메뉴를 취소로 닫기
- [ ] 다시 열어 uuid-* 변경 여부 확인

메뉴 범위 밖의 같은 텍스트 버튼을 수집하지 않도록 새로 열린 팝업 조상 안에서만 탐색한다.

### V6. 수업 없는 날

- [ ] 수업 없는 날짜 셀 우클릭
- [ ] 메뉴가 열리지 않는지 또는 비활성 상태인지 확인
- [ ] 같은 교시의 정상 날짜와 비교
- [ ] 이를 타임아웃이 아닌 CellUnavailable로 분류 가능한 신호 기록

## 4. 최초 실측 스냅샷

검증일: 2026-08-18

### 확인된 값

| 항목 | 실측 |
|---|---|
| 시간표 앱 ID | edu/sw/els/edc/tm/els_edctm00_m00$1 |
| 주차 그리드 | grdWeek |
| 시수 그리드 | grdSisu |
| 시간표 그리드 | grdWeekByClsByTi |
| 시간표 논리 행 | 8(1~8교시) |
| 시간표 논리 열 | 8(교시+월~일) |
| 메뉴 스크롤 높이 | client 360 / scroll 636 |
| 메뉴 최대 scrollTop | 276 |
| DOM 메뉴 버튼 | 29 |
| 수업·교사 후보 | 20 |
| 작업 명령 | 9 |

### 관찰

- 메뉴 항목은 모두 DOM에 있었고 가상 목록은 아니었다.
- 화면 밖 항목은 실제 메뉴 스크롤 컨테이너에 가려져 있었다.
- 메뉴를 다시 열자 uuid-* ID가 변경됐다.
- 그리드 데이터는 CLX API로 읽을 수 있었지만 팝업 항목은 일반 CLX 컨트롤 순회에서 발견되지 않았다.
- 수업이 없는 날짜는 우클릭해도 메뉴가 열리지 않았다.
- 다른 정상 주차에서는 같은 위치의 메뉴가 열렸다.
- 메뉴는 취소로 닫았고 수업 선택과 저장은 수행하지 않았다.

### 확인된 작업 명령

- 결보강처리
- 보강등록(현장체험학습)
- 행사처리
- 공백삽입
- 공백삭제
- 수업삭제
- 전체 수업삭제
- 교사추가
- 취소

메뉴 개수와 후보 개수는 다른 환경에서 달라질 수 있으므로 상수로 사용하지 않는다.

## 5. 쓰기 시험 승급 절차

읽기 전용 V1~V6이 모두 통과한 뒤에만 진행한다.

### W1. 단일 셀, 저장 안 함

사용자에게 시험 셀과 목표 항목을 다시 확인받는다.

- [ ] 현재 셀이 비어 있음
- [ ] 실제 날짜·교시 일치
- [ ] 대상 과목·교사 안정 키가 현재 메뉴에 정확히 한 건
- [ ] 특수 명령이 아님
- [ ] 대상이 화면 밖이면 메뉴 스크롤 후 재탐색
- [ ] 클릭
- [ ] 셀 표시와 CLX 값을 다시 읽어 목표와 일치
- [ ] 저장하지 않음
- [ ] 사용자가 화면에서 결과 확인
- [ ] 화면 재조회 또는 사용자 조작으로 원상 복구

실패하면 W2로 넘어가지 않는다.

### W2. 단일 셀 멱등성

- [ ] W1과 같은 목표를 다시 실행
- [ ] 이미 일치로 판정
- [ ] 메뉴를 열거나 변경하지 않음
- [ ] 결과에 건너뜀으로 기록

### W3. 메뉴 스크롤 밖 옵션

- [ ] 목록 아래쪽의 안전한 수업 후보 선택
- [ ] 페이지 전체가 아니라 메뉴 스크롤만 이동
- [ ] 스크롤 뒤 대상 안정 키 재확인
- [ ] 입력 후 셀 재검증
- [ ] 저장하지 않고 복구

### W4. 복수 교사

- [ ] 같은 과목의 교사 A/B가 별도 안정 키인지 확인
- [ ] 사용자가 지정한 교사만 선택
- [ ] 첫 후보 또는 과목명만으로 선택하지 않음
- [ ] 입력 후 과목과 교사 모두 재검증
- [ ] 저장하지 않고 복구

### W5. 창체

자율·자치활동, 동아리활동, 진로활동을 각각 별도 시험한다.

- [ ] 세부 종류
- [ ] 담당 교사
- [ ] 메뉴 안정 키
- [ ] 입력 후 표시
- [ ] 복구

### W6. 한 주, 저장 안 함

- [ ] 매우 작은 주 또는 일부 셀만 대상으로 계획
- [ ] 모든 셀 입력 후 전부 재검증
- [ ] 한 셀 실패 시 즉시 중단
- [ ] 변경된 셀 목록 기록
- [ ] 저장하지 않음
- [ ] 사용자 확인 후 원상 복구

## 6. 저장 시험

저장은 별도 승인 범위다. 사용자가 “이 주를 저장해도 된다”고 명확히 정한 시험에서만 수행한다.

### S1. 단일 주 저장

- [ ] 저장 직전 목표 셀 전체 재검증
- [ ] 예상 밖 변경 없음
- [ ] 저장 버튼 상태 확인
- [ ] 저장 클릭
- [ ] 대화상자 제목·본문·버튼 텍스트 수집
- [ ] 허용된 저장 확인창인지 타입 판정
- [ ] 확인
- [ ] 완료 대화상자도 허용 타입인지 판정
- [ ] 같은 주 재조회
- [ ] 모든 목표 셀 재검증
- [ ] 결과와 체크포인트 기록

알 수 없는 대화상자가 나오면 자동으로 아무 버튼도 누르지 않고 중단한다.

### S2. 저장 실패

다음을 각각 안전한 테스트 더블 또는 허용된 실기기 상황에서 확인한다.

- [ ] 확인창 구조 변경
- [ ] 네트워크 오류
- [ ] 세션 만료
- [ ] 저장 후 일부 셀 불일치
- [ ] 저장 버튼 비활성/변경 없음

저장 요청이 성공했다는 메시지만으로 체크포인트를 완료하지 않는다. 재조회 일치가 필요하다.

## 7. 연간 배치·중단·재개 시험

### B1. 두 주 배치

- [ ] 첫 주 입력·검증·저장·재조회
- [ ] 첫 주 체크포인트
- [ ] 다음 주로 이동
- [ ] 두 번째 주 입력
- [ ] 첫 주 값이 유지되는지 확인

### B2. 입력 도중 취소

- [ ] 셀 입력 사이에 취소
- [ ] 새 상호작용을 즉시 시작하지 않음
- [ ] 현재 열린 메뉴를 안전하게 닫음
- [ ] 미저장 변경 셀 목록 보고
- [ ] 해당 주 완료 체크포인트 없음

### B3. 세션 만료

- [ ] 만료를 일반 셀 실패와 구분
- [ ] 저장 시도 금지
- [ ] 사용자가 재로그인
- [ ] 현재 학년·반·주차 재확인
- [ ] 현재 셀 값을 다시 읽어 계획 재생성

### B4. 앱 재시작 후 재개

- [ ] 원본 파일 해시와 계획 ID 확인
- [ ] 카탈로그 지문 확인
- [ ] 완료 주도 현재 값을 재조회
- [ ] 불일치하면 자동 건너뛰지 않음
- [ ] 미완료 주부터 재계획

### B5. 재실행

- [ ] 전체가 이미 일치하면 변경 0건
- [ ] 일부만 일치하면 나머지만 입력 예정
- [ ] 기존 다른 값은 충돌로 유지

## 8. 화면 개편 시 재검증 순서

나이스가 바뀌었을 때 바로 셀렉터 문자열부터 수정하지 않는다.

1. V1 화면 식별
2. V2 CLX 컨트롤 목록
3. V3 날짜 데이터
4. V4 셀 원시 값
5. V5 열린 메뉴 구조와 스크롤
6. 저장 전/후 표시 형식
7. Automation의 시간표 전용 진단 DTO
8. 파서·어댑터 단위 테스트 픽스처
9. 원격 셀렉터가 가능한 값
10. 코드 배포가 필요한 구조 변화

수정 위치 후보:

- NeisTarget/NeisScreenKind
- NeisSelectors의 시간표 키
- TimetableDomInspector
- TimetableClxReader
- TimetableMenuReader
- TimetableCellWriter
- 저장 대화상자 분류기

실제 클래스명은 구현 때 기술 설계와 개발문서에 반영한다.

  "grids": [

      "id": "grdWeekByClsByTi",

  "menu": {
    "totalItems": 29,

## 11. 즉시 중단 조건

다음 중 하나면 해당 시험을 중단한다.

- 목표 학년도·학기·학년·반이 아님
- 실제 날짜를 확정할 수 없음
- 메뉴 탐색 범위를 열린 팝업으로 제한할 수 없음
- 대상 옵션이 0개 또는 2개 이상
- 대상이 특수 명령과 구분되지 않음
- 기존 셀 값이 예상과 다름
- 알 수 없는 대화상자 출현
- 로그인 세션 종료
- 입력 후 재검증 불일치
- 저장 후 재조회 불일치
- 개인정보 마스킹이 보장되지 않음

중단은 실패가 아니라 안전 동작이다. 다음 셀이나 다음 주로 자동 진행하지 않고 진단 자료와 현재 변경 범위를 남긴다.
