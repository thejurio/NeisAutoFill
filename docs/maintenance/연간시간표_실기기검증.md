# 연간 시간표 자동입력 — 나이스 실기기 검증 절차

상태: 최초 실측 기준 작성  
최종 갱신: 2026-08-18  
관련 문서: [기술 설계](../architecture/연간시간표_기술설계.md) · [개발 로드맵](../roadmap/연간시간표_자동입력_로드맵.md)

이 문서는 나이스 화면을 실제로 확인하거나 자동화 어댑터를 변경할 때 따르는 안전 절차다. 화면 개편, 교육청별 차이, 메뉴 구조 변경에 대응할 수 있도록 “무엇을 확인했고 무엇은 아직 가정인지”를 기록한다.

---

## 1. 원칙

1. 로그인과 인증서는 사용자가 직접 처리한다.
2. 읽기 전용 진단을 쓰기 시험보다 먼저 완료한다.
3. 실제 교사명·계정 ID·학교명·사용자 경로를 저장소에 커밋하지 않는다.
4. 테스트는 빈 셀 한 건에서 시작하고, 저장은 별도 승인 단계에서만 한다.
5. 수업 후보가 아닌 명령은 절대 시험 선택하지 않는다.
6. 알 수 없는 확인창은 자동 승인하지 않는다.
7. 클릭 성공이 아니라 셀 재읽기와 저장 후 재조회로 성공을 판정한다.
8. 한 단계가 실패하면 더 넓은 범위 시험으로 넘어가지 않는다.

---

## 2. 시험 전 준비

### 사용자 확인

- [ ] 시험용 학년도·학기·학년·반을 사용자가 확인
- [ ] 변경해도 되는 빈 날짜·교시를 사용자가 지정
- [ ] 저장하지 않는 시험인지 저장 시험인지 명확히 구분
- [ ] 저장 시험이면 원래 값과 복구 방법을 기록
- [ ] 세션 만료까지 남은 시간이 충분한지 확인
- [ ] 실제 업무 시간표에 영향이 없는 범위인지 확인

### 프로그램 확인

- [ ] 현재 브랜치와 커밋 기록
- [ ] 전체 dotnet test 통과
- [ ] 시간표 진단 모드가 쓰기 동작을 하지 않는지 코드 검토
- [ ] 로깅 마스킹 활성화
- [ ] 진단 파일 저장 경로 확인
- [ ] 자동 저장 기본값 OFF
- [ ] 취소 토큰과 긴급 중단 동작 확인

### 자료 비식별화

원본 진단 파일을 공유하거나 커밋하기 전에 다음 값을 치환한다.

| 실제 값 | 치환 예 |
|---|---|
| 학교명 | SCHOOL_A |
| 교사명 | 교사A, 교사B |
| 로그인 ID | user-a |
| 교사 계정 ID | account-a |
| 사용자 폴더 | C:\Users\USER |
| 학생 정보 | 전부 삭제 |

단순 화면 블러만으로 끝내지 않는다. DOM 텍스트, JSON, 툴팁, aria-label, 파일명에도 실제 값이 남을 수 있다.

### 관찰

- 메뉴 항목은 모두 DOM에 있었고 가상 목록은 아니었다.
- 화면 밖 항목은 실제 메뉴 스크롤 컨테이너에 가려져 있었다.
- 메뉴를 다시 열자 uuid-* ID가 변경됐다.
- 그리드 데이터는 CLX API로 읽을 수 있었지만 팝업 항목은 일반 CLX 컨트롤 순회에서 발견되지 않았다.
- 수업이 없는 날짜는 우클릭해도 메뉴가 열리지 않았다.
- 다른 정상 주차에서는 같은 위치의 메뉴가 열렸다.
- 메뉴는 취소로 닫았고 수업 선택과 저장은 수행하지 않았다.

## 4-A. 2차 실측 (2026-08-18, 앱 자동화로 재확인)

CDP 로 연결된 전용 Edge 에서 읽기 전용 진단을 수행했다. **셀 선택·저장은 하지 않았고 메뉴는 [취소]로 닫았다.**

### 재확인된 값 (1차 실측과 일치)

| 항목 | 1차 | 2차 | 일치 |
|---|---|---|---|
| 시간표 그리드 논리 행 | 8 | 8 | ✅ |
| 메뉴 전체 항목 | 29 | 29 | ✅ |
| 수업·교사 후보 | 20 | 20 | ✅ |
| 작업 명령 | 9 | 9 (이름까지 동일) | ✅ |
| 메뉴 스크롤 | client 360 / scroll 636 / max 276 | 동일 | ✅ |

### 새로 확인된 사실

- **DOM 에 `grdWeekByClsByTi` 라는 id 는 없다.** CLX 내부 id 일 뿐이라 `document.getElementById` 로 찾지 못한다.
  DOM 특정은 구조로 한다 — `div.cl-grid[role=grid]` 중 렌더된 첫 행의 셀이 8개이고 첫 셀이 `N교시` 인 그리드.
  (참고: 이 환경의 시간표 그리드는 `aria-colcount=15`, `aria-rowcount=9` 로 **논리 8×8 과 다르다** — aria 로 세지 말 것)
- **셀 표시 형식과 메뉴 항목 형식이 다르다.**
  - 메뉴: `과목(교사(계정))`
  - 셀 : `과목` + 줄바꿈 + `(교사(계정))`
  두 형식이 **같은 안정 키**를 만들어야 현재 값과 목표를 비교할 수 있다(테스트로 고정함).
- **계정 형식이 두 가지다.** 일반 로그인 ID 와 `#P1000014282608001` 같은 내부 식별자가 섞여 있다.
- **복수 교사가 실제로 존재한다.** 이 환경에서 과학 3명, 자율·자치활동 3명, 도덕·수학·영어 각 2명.
  D-006(첫 항목 자동 선택 금지)이 이론이 아니라 실무 요건임이 확인됐다.
- **메뉴의 실제 스크롤 조상은 `cl-layout-content`** 였다(1차 기록의 `.cl-layout.cl-scrollbar` 와 클래스명이 다름).
  클래스명을 고정하지 말고 "`취소` 버튼의 조상 중 `scrollHeight > clientHeight` 인 첫 요소"로 찾는 편이 안전하다.
- 메뉴 항목 id 는 `uuid-33e` 처럼 매번 바뀐다 — 1차 관찰 재확인(D-004).
- **학기 시작 전 날짜는 우클릭해도 메뉴가 열리지 않는다.** (사용자 확인)
  1주차는 08/17(월)~08/23(일)이고 개학이 08/19(수)라, 월·화 셀에서는 메뉴가 열리지 않았고 수요일부터 열렸다.
  → `CellUnavailable` 로 분류할 정상 동작이며, 실패로 처리하면 안 된다.
- 주차 그리드(`grdWeek`) 필드: `weekBgngYmd`, `weekEndYmd`, `weekCntNm`, `event`, `sbjtNotCnt`, `weekCnt`.
  주차 이동은 이 그리드의 행을 클릭하면 되고, 이때 시간표 그리드가 해당 주로 갱신된다.
- 시수 그리드(`grdSisu`) 필드: `ctr`(학기), `cn`(기준시수/편차), `sbjtCd{과목코드}_{교사·활동코드}` 열들.
  T6 의 "기준 시수 대비 계획 시수" 비교에 쓸 수 있다.

### ⚠ 셀 값은 HTML 이다 (가장 중요한 발견)

CLX `{day}Otpt` 필드는 평문이 아니라 **HTML 마크업**으로 온다. DOM 의 innerText 와 다르다.

~~~text
<div></div>과학<br/>(교사A(account-a))
<div></div>과학<font style="color:deeppink;"><br/>(교사A(account-a))</font>
~~~

태그를 걷어내지 않으면 과목명이 `<div></div>과학<br/>` 이 되어 **모든 매칭이 실패**한다.
`TimetableTextNormalizer.StripMarkup` 이 `<br/>`→줄바꿈 변환과 태그 제거를 담당하며,
분홍색 `<font>` 로 감싸인 셀도 같은 값이 나오도록 테스트로 고정했다.
(분홍색이 무엇을 뜻하는지는 아직 모른다 — 저장 전 변경 표시로 추정되나 미확인.)

### 주차 목록 범위와 그리드 날짜 범위가 다르다

- 주차 그리드(`grdWeek`)의 `weekBgngYmd~weekEndYmd` = **수업일 범위** (1주차 = 08/19~08/23)
- 시간표 그리드의 요일 열 = **월~일 7일 전체** (1주차 = 08/17~08/23)

주차 이름만 보고 날짜를 유추하면 안 되고, 셀 주소는 항상 행의 `{day}Ymd` 를 쓴다.

### 최종 확인 — 읽기부터 실행 계획까지 (2026-08-18)

`TimetableReader` + Core 파이프라인을 실제 화면에 붙여 확인했다. **쓰기·저장 없음.**

| 항목 | 결과 |
|---|---|
| 주차 목록 | 28개 정상 |
| 현재 주 셀 | 56칸(8교시×7일), 경고 0건 |
| 값이 있는 셀 | 6칸을 안정 키로 변환 성공 |
| 카탈로그 | 후보 20 · 명령 9 · 지문 생성 |
| 학기 시작 전 열 | 메뉴 미표시 → CellUnavailable 로 자동 분류 |

평일 1교시 5칸에 가상의 계획을 세워 분류한 결과:

~~~text
08-17(월) CellUnavailable   학기 시작 전
08-18(화) CellUnavailable   학기 시작 전
08-19(수) AlreadyMatches    이미 같은 값 → 건너뜀
08-20(목) Pending           입력 예정
08-21(금) Pending           입력 예정
→ 입력 예정 2 · 막힘 0 · 실행 가능 true
~~~

`AlreadyMatches` 가 나왔다는 것은 **셀 HTML → 안정 키** 와 **메뉴 항목 → 안정 키** 가 실제로 일치했다는 뜻이다.
현재 값과 목표를 비교하는 전제가 실기기에서 성립함을 확인했다.

### 화면 이동·조회·주차 선택 (2026-08-18 확정)

| 단계 | 방법 | 주의 |
|---|---|---|
| 이동 | 학급담임 → **시간표관리** → 학급시간표관리 | 2단계가 평가·서술문의 [학생평가]와 다르다 |
| 도착 판정 | `div.app-tit` 가 **"학급시간표"** 를 포함 | 메뉴 라벨은 `학급시간표관리`(붙임), 화면 제목은 `학급시간표 관리`(**띄어쓰기**) |
| 조회 | 기존 `QueryAsync()` 재사용 | 조회하면 **주차 목록만** 채워진다 |
| 주차 선택 | 주차 그리드 행 클릭 | 여기까지 해야 시간표 그리드가 그려진다 |

**이동 직후에는 그리드가 없다.** 화면 도착 판정에 그리드 유무를 쓰면 영영 도착으로 잡히지 않는다
(서술문 화면과 같은 함정). `IsTimetableScreenAsync`(제목)와 `HasGridAsync`(그리드)를 분리한 이유다.

### 전체 흐름 실기기 통과 기록 (2026-08-18)

~~~text
[1] 이동            True
[2] 조회            True
[3] 화면 인식 True · 그리드 있음 False   ← 조회만으로는 그리드가 없다
[4] 주차 선택       1주차 (2026.08.19.~2026.08.23.) → 그리드 있음 True
[5] 셀 56칸 · 값 있는 셀 6칸 · 경고 0 · 날짜 08-17~08-23
[6] 카탈로그        후보 20 · 명령 9 · 지문 eda11fdbe08ffa5b
[7] 계획            CellUnavailable 2 · AlreadyMatches 1 · Pending 2 · 실행 가능 true
~~~

기존 경로 회귀도 함께 확인했다 — [교과별 평가]·[학기말종합의견] 이동 모두 정상,
같은 화면 재이동은 메뉴 클릭 없이 740ms 내 즉시 true.

### 확정된 CLX 필드 목록 (진단 리포트로 재확인)

~~~text
grdWeek            weekBgngYmd, weekEndYmd, weekCntNm, event, sbjtNotCnt, weekCnt
grdSisu            shlCd, ayr, sem, grd, clsNm, clsCd, ctr, cn,
                   sbjtCd{과목코드}_{교사·활동코드} … (학교마다 다름)
grdWeekByClsByTi   pir, pirOtpt,
                   monOtpt … sunOtpt   (표시값 — HTML)
                   monInfo … sunInfo   (부가 정보)
                   monYmd  … sunYmd    (날짜, yyyyMMdd)
~~~

⚠ **`{day}Otpt`·`{day}Info` 는 값이 있는 주에서만 나타난다.** 시간표가 비어 있는 주를 읽으면
`pir`·`{day}Ymd` 만 오므로, 필드가 없다는 이유로 실패 처리하면 안 된다(빈 셀로 취급한다).

진단은 `TimetableDiagnostics.CaptureAsync()` 로 뽑는다 — 교사명·계정을 교사A/account-a 로 치환해
그대로 공유·커밋할 수 있다.

### 범위 식별값 읽기 (2026-08-19 확정)

| 항목 | 읽는 방법 |
|---|---|
| 학년도·학기·학년·반 | 콤보의 `aria-label="학년도, 2026"` 형식 — 쉼표 뒤가 값 |
| 학교명 | 보이는 요소 중 텍스트가 `…초등학교/중학교/고등학교/학교` 로 끝나는 것 |
| 로그인 사용자 | 텍스트가 `이름(계정)` 형태인 요소 |

학교·사용자는 읽는 즉시 **해시로 바꿔** 보관한다(`TimetableProfileScope.Create`). 원문은 남기지 않는다.

### ⚠ 안정 키에 교사명이 들어가면 개인정보가 파일에 남는다

`StableKey` 는 매핑 프로필(`timetable_mappings.json`)과 진단 리포트에 **그대로 저장**된다.
처음 구현에서 `L|과학|이문성|#p1000014282608001` 처럼 원문이 들어가 실제로 파일에 남는 것을 확인했다.
→ 교사명·계정은 짧은 해시로 바꿨다: `L|과학|9fdcd68f|be43edc5` (과목명은 개인정보가 아니라 유지).
카탈로그와 규칙이 같은 방식으로 키를 만들므로 대조에는 영향이 없다.

### 미확인 / 다음에 볼 것

- **2주차(08/24~08/30)에서는 평일 20칸 어디서도 메뉴가 열리지 않았다.** 학기 시작 후인데도 열리지 않은 이유가
  아직 설명되지 않는다(해당 주 시간표가 아직 편성되지 않아서일 가능성). 주차별로 메뉴 가용성을 확인하는 절차가 필요하다.
- 값이 있는 셀에서의 우클릭 동작(수업 변경 메뉴가 다른지)은 확인하지 않았다.

|---|---|---|

### ⚠ 저장 전과 저장 후의 셀 표기가 다르다 (R-006 확인)

이번 시험에서 실제로 드러났고, 처음엔 **정상 입력을 실패로 오판**했다.

| 상황 | 셀 표시 |
|---|---|
| 메뉴 항목 | `국어(진두성(thejurio))` — 계정 있음 |
| **입력 직후(저장 전)** | `국어⏎(진두성)` — **계정 없음** |
| 저장된 값(기존 셀) | `과학⏎(이문성(#P1000…))` — 계정 있음 |

→ 재검증은 정확 키가 어긋나면 **계정을 뺀 키(LooseKey)** 로 한 번 더 본다.
단 그 키가 카탈로그에서 **유일할 때만** 인정한다 — 동명이인을 얼버무리지 않기 위해서다.

### ⚠ mon/tue/… 접두사는 요일이 아니라 열 순서다

같은 1주차인데 날짜 배치가 달랐다.

~~~text
2026-08-18 관찰: monYmd=08-17(월) … sunYmd=08-23(일)   ← 월~일
2026-08-19 관찰: monYmd=08-19(수) … sunYmd=08-25(화)   ← 주차 시작일부터 7일
~~~

접두사를 요일로 믿고 계산하면 **엉뚱한 날에 입력한다.** 날짜는 오직 `{day}Ymd` 값에서 얻고,
클릭할 열은 스냅샷의 `ColumnOf(날짜)` 로 되찾는다. 입력 직전에 `ReadCellDateAsync` 로 한 번 더 교차 확인한다.

### ⚠ 미저장 변경이 있으면 주차를 옮길 수 없다 (가장 중요한 발견)

미저장 상태에서 주차 행을 클릭하면 나이스가 이 대화상자를 띄우고 화면이 멈춘다.

~~~text
확인
시간표에 변경된 항목이 존재합니다.
조회전에 저장하셔야합니다.
저장하시겠습니까?
        [확인]  [취소]
~~~

**[확인]을 누르면 저장된다.** 자동으로 누르지 않는다(D-010). 대응:

1. `HasSaveDialogAsync()` 로 감지하고, 주차 이동 중 뜨면 **예외로 중단**하고 사용자에게 넘긴다
2. `DismissSaveDialogAsync()` 는 <b>[취소]만</b> 누른다 — 저장하지 않고 변경을 버린다
3. `SelectWeekForDateAsync` 는 **이미 그 주가 떠 있으면 클릭하지 않는다** — 대화상자를 애초에 만들지 않는 것이 최선

### ⚠ 저장 전 표기 때문에 재계획이 전부 충돌로 잠기던 문제

입력 직후 셀은 계정이 빠진다(`국어(교사A)`). 계획 단계가 이걸 모르면 **방금 넣은 20칸을
'기존에 다른 수업이 있다'로 오판**해 재실행이 통째로 잠긴다. 실제로 W6 재계획에서 확인했다.
→ 계정이 빈 키는 LooseKey 로 비교하되 카탈로그에서 유일할 때만 인정한다.

## 4-D. 세션 만료를 실제로 만남 (2026-08-19, B3)

W6 뒤 미저장 20칸을 버리려고 다른 화면으로 이동하는데 **이동·조회가 모두 조용히 실패**했다.
화면을 들여다보니 세션이 끊겨 있었다.

~~~text
로그아웃 되었습니다.
업무를 진행하시려면 다시 로그인 해 주세요.
여기를 눌러 로그인으로 이동하세요
~~~

**문서 제목은 그대로였다.** 나이스는 SPA 라 세션이 끊겨도 화면 안에 안내 상자만 뜬다.
제목만 보던 `DetectStatusAsync` 는 이걸 놓쳐 `OtherNeisPage` 로 판정했고,
이동·조회 실패의 원인을 알 수 없었다.

→ 화면 안의 "로그아웃 되었습니다"·"다시 로그인" 문구도 함께 보도록 고쳤다.
이제 `LoggedOut` 으로 정확히 판정되어 상태칩과 안내가 제 역할을 한다.
**이 문제는 시간표만이 아니라 성적·서술문 입력에도 똑같이 있었다.**

부수 효과: 세션이 끊기면서 미저장 변경 20칸도 함께 사라졌다 —
미저장 상태로 오래 두면 작업이 날아간다는 뜻이기도 하다.

## 4-E. S1 저장 시험 (2026-08-19, 사용자 승인 · 실제로 저장함)

작은 범위로 하기로 하여 **1칸만** 저장했다. 2주차(08-24) 월요일 1교시에 국어를 넣고 저장.

| 단계 | 결과 |
|---|---|
| 1칸 입력 | ✅ Written |
| [저장] 버튼 상태 | ✅ 활성 (변경 없으면 비활성 — 저장 생략 판단에 쓸 수 있다) |
| 확인 대화상자 | `저장하시겠습니까?` [확인] [취소] |
| 완료 대화상자 | `저장되었습니다. 교과진도표관리를 확인하시기 바랍니다.` [확인] |
| **재조회 검증** | ✅ 3주차로 갔다가 2주차로 돌아와도 **1칸 그대로 남음** |

### ⚠ 확인창 버튼은 element.click() 이 먹지 않는다

셀 우클릭 메뉴 항목은 `element.click()` 으로 눌렸는데, **저장 확인창 버튼은 반응하지 않았다.**
좌표를 얻어 <b>실제 마우스 클릭</b>(`Mouse.ClickAsync`)을 보내야 눌린다.
같은 화면 안에서도 컨트롤마다 다르니, 안 눌리면 마우스 클릭으로 바꿔 본다.

### ✅ R-006 확정 — 저장 전후 표기가 정말 다르다

| 시점 | 셀 표시 | 계정 |
|---|---|---|
| 입력 직후(저장 전) | `국어⏎(교사명)` | **없음** |
| **저장 후** | `국어⏎(교사명(계정))` | **있음** |

가설이 아니라 같은 셀에서 확인한 사실이다. 그래서 재검증·계획 비교는
계정이 빠진 키(LooseKey)도 함께 봐야 한다 — 카탈로그에서 유일할 때만 인정한다.

### 저장한 것을 되돌리려면

프로그램은 <b>수업삭제 같은 특수 명령을 쓰지 않는다</b>(불변조건 7). 되돌리기는 사람이 한다:
해당 셀을 우클릭해 [수업삭제]를 고르고 저장한다.

## 4-F. B1 배치 러너 검증 (2026-08-19, 쓰기 없음)

주 단위 배치 러너(입력→저장→재조회→체크포인트)의 <b>판단 경로</b>를 실기기에서 확인했다.

| 시험 | 계획 | 기대 | 결과 |
|---|---|---|---|
| ① 이미 다 맞음 | 화면의 현재 값 29칸을 그대로 목표로 | 아무것도 쓰지 않고 완료 | ✅ `할 일 없음 (이미 맞음·건너뜀 29칸)` · 입력 0칸 |
| ② 기존 값과 다름 | 한 칸만 다른 과목으로 | 쓰기 전에 중단 | ✅ `기존에 다른 수업이 들어 있습니다` · 입력 0칸 |
| ③ 이미 완료된 주 | 체크포인트에 그 주가 있음 | 다시 훑지 않음 | ✅ `앞선 실행에서 이미 끝냈습니다` |

①은 화면에서 읽은 29칸이 <b>전부</b> 계획과 같다고 판정됐다는 뜻이다 —
읽기·파싱·안정키·값 비교가 실기기에서 한 줄로 맞물린다는 확인이다.

### ⚠ 나이스 학급시간표는 이미 채워져 있을 수 있다

이 검증 도중 08-24 주가 <b>29칸 모두 채워진 상태</b>로 바뀐 것을 확인했다
(기준시간표에서 일괄 생성된 것으로 보인다). S1 에서 넣었던 1칸도 그 과정에서 사라졌다.

이것은 예외가 아니라 <b>평범한 상황</b>일 수 있다. 그렇다면 연간 자동입력의 실제 쓰임은
"빈 칸을 채우는 것"이 아니라 "이미 있는 값을 계획대로 고치는 것"이 된다.
지금 규칙(D-010: 기존 값이 다르면 덮어쓰지 않고 막는다)에서는 모든 칸이 잠긴다.
→ 사용자와 정할 것: 덮어쓰기를 어떤 형태로 허용할지 (로드맵 T8 미해결).

### 토요휴업일

토요일 칸에는 1~8교시 전부 `토요휴업일` 이 값으로 들어 있다.
카탈로그(입력 가능 항목)에는 없으므로 계획에서 자연히 제외된다 — 위 ①에서 8칸이 그렇게 빠졌다.

- [ ] 대상이 화면 밖이면 메뉴 스크롤 후 재탐색
- [ ] 클릭
- [ ] 셀 표시와 CLX 값을 다시 읽어 목표와 일치
- [ ] 저장하지 않음
- [ ] 사용자가 화면에서 결과 확인
- [ ] 화면 재조회 또는 사용자 조작으로 원상 복구

실패하면 W2로 넘어가지 않는다.

### W2. 단일 셀 멱등성

- [ ] W1과 같은 목표를 다시 실행
- [ ] 이미 일치로 판정
- [ ] 메뉴를 열거나 변경하지 않음
- [ ] 결과에 건너뜀으로 기록

### W3. 메뉴 스크롤 밖 옵션

- [ ] 목록 아래쪽의 안전한 수업 후보 선택
- [ ] 페이지 전체가 아니라 메뉴 스크롤만 이동
- [ ] 스크롤 뒤 대상 안정 키 재확인
- [ ] 입력 후 셀 재검증
- [ ] 저장하지 않고 복구

### W4. 복수 교사

- [ ] 같은 과목의 교사 A/B가 별도 안정 키인지 확인
- [ ] 사용자가 지정한 교사만 선택
- [ ] 첫 후보 또는 과목명만으로 선택하지 않음
- [ ] 입력 후 과목과 교사 모두 재검증
- [ ] 저장하지 않고 복구

### W5. 창체

자율·자치활동, 동아리활동, 진로활동을 각각 별도 시험한다.

- [ ] 세부 종류
- [ ] 담당 교사
- [ ] 메뉴 안정 키
- [ ] 입력 후 표시
- [ ] 복구

### W6. 한 주, 저장 안 함

- [ ] 매우 작은 주 또는 일부 셀만 대상으로 계획
- [ ] 모든 셀 입력 후 전부 재검증
- [ ] 한 셀 실패 시 즉시 중단
- [ ] 변경된 셀 목록 기록
- [ ] 저장하지 않음
- [ ] 사용자 확인 후 원상 복구

## 6. 저장 시험

저장은 별도 승인 범위다. 사용자가 “이 주를 저장해도 된다”고 명확히 정한 시험에서만 수행한다.

### S1. 단일 주 저장

- [ ] 저장 직전 목표 셀 전체 재검증
- [ ] 예상 밖 변경 없음
- [ ] 저장 버튼 상태 확인
- [ ] 저장 클릭
- [ ] 대화상자 제목·본문·버튼 텍스트 수집
- [ ] 허용된 저장 확인창인지 타입 판정
- [ ] 확인
- [ ] 완료 대화상자도 허용 타입인지 판정
- [ ] 같은 주 재조회
- [ ] 모든 목표 셀 재검증
- [ ] 결과와 체크포인트 기록

알 수 없는 대화상자가 나오면 자동으로 아무 버튼도 누르지 않고 중단한다.

### S2. 저장 실패

다음을 각각 안전한 테스트 더블 또는 허용된 실기기 상황에서 확인한다.

- [ ] 확인창 구조 변경
- [ ] 네트워크 오류
- [ ] 세션 만료
- [ ] 저장 후 일부 셀 불일치
- [ ] 저장 버튼 비활성/변경 없음

저장 요청이 성공했다는 메시지만으로 체크포인트를 완료하지 않는다. 재조회 일치가 필요하다.

## 7. 연간 배치·중단·재개 시험

### B1. 두 주 배치

- [ ] 첫 주 입력·검증·저장·재조회
- [ ] 첫 주 체크포인트
- [ ] 다음 주로 이동
- [ ] 두 번째 주 입력
- [ ] 첫 주 값이 유지되는지 확인

### B2. 입력 도중 취소

- [ ] 셀 입력 사이에 취소
- [ ] 새 상호작용을 즉시 시작하지 않음
- [ ] 현재 열린 메뉴를 안전하게 닫음
- [ ] 미저장 변경 셀 목록 보고
- [ ] 해당 주 완료 체크포인트 없음

### B3. 세션 만료

- [ ] 만료를 일반 셀 실패와 구분
- [ ] 저장 시도 금지
- [ ] 사용자가 재로그인
- [ ] 현재 학년·반·주차 재확인
- [ ] 현재 셀 값을 다시 읽어 계획 재생성

### B4. 앱 재시작 후 재개

- [ ] 원본 파일 해시와 계획 ID 확인
- [ ] 카탈로그 지문 확인
- [ ] 완료 주도 현재 값을 재조회
- [ ] 불일치하면 자동 건너뛰지 않음
- [ ] 미완료 주부터 재계획

### B5. 재실행

- [ ] 전체가 이미 일치하면 변경 0건
- [ ] 일부만 일치하면 나머지만 입력 예정
- [ ] 기존 다른 값은 충돌로 유지

## 11. 즉시 중단 조건

다음 중 하나면 해당 시험을 중단한다.

- 목표 학년도·학기·학년·반이 아님
- 실제 날짜를 확정할 수 없음
- 메뉴 탐색 범위를 열린 팝업으로 제한할 수 없음
- 대상 옵션이 0개 또는 2개 이상
- 대상이 특수 명령과 구분되지 않음
- 기존 셀 값이 예상과 다름
- 알 수 없는 대화상자 출현
- 로그인 세션 종료
- 입력 후 재검증 불일치
- 저장 후 재조회 불일치
- 개인정보 마스킹이 보장되지 않음

중단은 실패가 아니라 안전 동작이다. 다음 셀이나 다음 주로 자동 진행하지 않고 진단 자료와 현재 변경 범위를 남긴다.
