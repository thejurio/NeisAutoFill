# 사용설명서 검증 기록

> 검증일: 2026-08-22  
> 기준 버전: v1.9.0  
> 사용자용 결과물: `docs/guide/사용설명서.html`

## 1. 문서 원본과 빌드 방식

- 편집 원본: `docs/guide/user-manual.template.html`
- 실제 화면: `docs/manual_shots/v1.9/*.png`
- 생성 명령: `powershell -ExecutionPolicy Bypass -File scripts/build-user-manual.ps1`
- 생성 결과는 이미지가 base64로 포함된 단일 HTML이다.
- 앱 프로젝트는 `docs/guide/사용설명서.html`을 출력 폴더의 `사용설명서.html`로 연결한다.
- 슬라이드 제목은 각 `<section class="slide" data-title="…">`에서 자동으로 목차에 반영된다. 별도 제목 배열을 관리하지 않는다.

이전에는 `docs/guide/사용설명서.html`과 `src/NeisAutoFill.App/사용설명서.html`이 서로 다른 내용으로 존재했다. 앱은 `src` 쪽만 배포했기 때문에 문서 수정이 실제 도움말에 반영되지 않았다. 이번 개편에서 원본을 하나로 통합했다.

### 사용자 안내 구조

- 첫 화면에서는 기능을 설명하지 않고 `평가 작업` 또는 `연간 시간표`를 고르게 한다.
- 평가 작업은 준비부터 저장 확인까지 10단계로 이어진다.
- 연간 시간표는 문서·나이스 준비부터 재시도까지 7단계로 이어진다.
- 각 단계는 `지금 할 행동 → 완료 확인 → 그 단계에서만 필요한 주의` 순서로 통일한다.
- 자동 저장 원리, 백업 범위, 진단자료 같은 참고 설명은 실제 필요한 단계 또는 마지막 참고 장에만 둔다.
- 전체 기능을 먼저 소개하는 참고서식 구성을 다시 도입하지 않는다. 사용자는 해당 작업을 처음부터 끝까지 그대로 따라갈 수 있어야 한다.

## 2. 개편안에서 그대로 채택하지 않은 내용

| 개편안의 전제 또는 제안 | 실제 확인 결과와 반영 내용 |
|---|---|
| 기존 설명서는 13장이다 | 앱이 실제 배포하던 설명서는 16장이었다. 새 설명서는 작업 선택 1장, 평가 따라하기 10장, 시간표 따라하기 7장, 문제 해결 1장의 19장으로 재구성했다. |
| 전담 교사 흐름은 본문에서 뺀다 | 전담 모드는 명단·반 관리와 문서 인식 흐름이 담임과 달라 삭제하지 않았다. 설정·모드 장과 입력 장에서 차이를 설명했다. |
| 잘못된 나이스 화면에서는 입력 버튼이 잠긴다 | 실제 활성 조건에는 현재 나이스 메뉴 확인이 포함되지 않는다. 버튼이 켜져 있어도 화면을 직접 확인하라고 경고했다. |
| 평가계획은 여러 교과를 함께 올린다 | 최초 코드 대조에서 교과 전환 호출이 빠진 것을 발견했다. 2026-08-22에 교과별 자동 전환·조회·표시값 재대조를 연결하고 여러 교과 절차로 바로잡았다. |
| 시간표의 문서 밖 칸은 건드리지 않는다 | 덮어쓰기를 켜면 문서가 다루는 날짜 안의 나이스 기존 수업이 삭제 대상이 될 수 있다. 첫 실행은 덮어쓰기 해제와 1주 시험을 권장했다. |
| 중지하면 해당 주는 저장되지 않으므로 안전하다 | 저장은 안 해도 미저장 변경이 화면에 남을 수 있다. 중지 후 나이스 `조회`로 변경을 버리는 절차를 넣었다. |
| PDF/HWP/HWPX는 양식과 무관하게 읽힌다 | 확인된 표는 로컬 파서가 처리하고 낯선 표는 AI가 시도할 뿐 성공을 보장하지 않는다. PDF를 가장 안정적인 형식으로 안내했다. |
| 모든 자료는 내 문서에 있고 백업 ZIP에 포함된다 | 설정·상태는 `%AppData%`에도 있으며 시간표 원본·매핑·체크포인트 등은 백업 ZIP 대상이 아니다. 별도 보관을 안내했다. |
| 창체 계획 문서를 현재 화면에서 올릴 수 있다 | 파서와 연결 로직은 있으나 v1.9.0 XAML에 불러오기 UI가 연결되지 않았다. 현 버전은 칸별 `과목 바꾸기`로 세부 활동을 정하도록 설명했다. |

## 3. 실제 화면 캡처 원칙

- 실행 중인 v1.9.0 프로그램에서 직접 촬영했다.
- 학생 이름과 평가 내용은 설명서용 가상 자료를 사용했다.
- 나이스 과목·교사 목록은 실제 교사명과 계정이 노출될 수 있어 불러오지 않은 상태로 촬영했다.
- 전체 화면을 무조건 축소하지 않고 작업에 필요한 영역을 직접 캡처했다.
- 캡처 후 픽셀을 가리거나 합성하지 않았다. 화면 옆 설명으로 조작 위치와 주의점을 안내한다.
- 나이스 입력·저장 명령은 캡처 과정에서 실행하지 않았다.

## 4. 코드와 대조한 핵심 동작

- 교과평가·서술문의 `이 과목 입력`은 자동 저장하지 않는다.
- 전과목·전체반 입력은 대상별 검증 뒤 자동 저장한다.
- 정확한 입력과 빠른 입력 설정은 교과평가·서술문에만 적용된다.
- 평가계획 올리기는 선택한 교과마다 나이스 교과를 자동으로 바꾸고 조회한 뒤, 표시 교과를 재대조하고 입력한다.
- 시간표 덮어쓰기는 v1.9.0 화면에서 기본 체크 상태다.
- 시간표는 한 주의 입력과 검증이 모두 성공했을 때 그 주를 저장한다.
- 시간표 실행 중 실패·중지 시 현재 주의 미저장 변경이 화면에 남을 수 있다.
- `국·수·사·과`는 표준 과목명으로 정규화하고, 학교별 미등록 표기는 사용자가 나이스 항목과 연결한다.
- 미분류 `창`은 자율·자치활동·동아리활동·진로활동 중 하나로 임의 확정하지 않는다.

## 5. 다음 버전에서 다시 확인할 항목

1. 앱 버전과 화면 크기를 확인하고 캡처 폴더를 새 버전으로 만든다.
2. 실제 나이스에서 서로 다른 두 교과로 자동 전환·조회·입력이 이어지는지 소규모로 확인한다.
3. 시간표 덮어쓰기 기본값과 삭제 범위를 확인한다.
4. 창체 계획 불러오기 UI가 연결됐는지 확인한다.
5. 한 과목/전과목/전체반의 자동 저장 정책을 확인한다.
6. 백업 ZIP 포함 범위를 `WorkspaceBackup` 코드와 대조한다.
7. 실제 화면 문구와 설명서 버튼명이 같은지 확인한다.
8. `scripts/build-user-manual.ps1`을 실행하고 슬라이드·이미지 검증을 통과시킨다.
9. 기본 도움말 창 1260×820과 최소 창 820×560에서 모든 장을 눈으로 확인한다.
10. 앱을 빌드해 출력 폴더의 `사용설명서.html`이 문서 원본과 같은지 확인한다.
