## 1. 최종 사용자 흐름

1. 연간 시간표 PDF/HWP/HWPX를 선택한다.
2. 필요하면 창체 계획 파일을 추가한다.
3. AI 인식 결과를 날짜·교시 표로 검토하고 잘못된 셀을 고친다.
4. 프로그램이 로그인된 나이스의 현재 반에서 과목·교사 목록을 읽는다.
5. 국, 수, 창 같은 원본 표기와 실제 과목·교사를 매핑한다.
6. 같은 과목의 교사가 여러 명이면 기본/요일/교시/날짜 예외를 정한다.
7. 창 셀은 창체 계획 또는 사용자 선택으로 자율·자치/동아리/진로를 확정한다.
8. 전체 연간 미리보기에서 미해결, 기존 값 충돌, 휴업일을 해결한다.
9. 주 단위로 입력하고 셀 값을 검증한다.
10. 초기 버전은 사용자가 저장하고, 안정화 뒤 명시적 동의형 주 단위 자동 저장을 제공한다.
11. 중단되면 현재 값을 다시 읽어 안전하게 이어서 실행한다.

## 2. 전체 완료 조건

다음 조건이 모두 충족돼야 기능 완료로 본다.

- 서로 다른 학교/사용자 환경에서 런타임 과목·교사 목록을 사용한다.
- PDF, HWP, HWPX 중 지원 가능한 입력 경로가 같은 중간 모델로 수렴한다.
- 한 글자 별칭과 사전에 없는 과목을 잃지 않는다.
- 복수 교사, 요일·교시별 교사, 특정 날짜 예외를 지원한다.
- 창을 세부 활동으로 임의 변환하지 않는다.
- 창체 전체 계획과 세부 계획의 중복이 한 수업으로 처리된다.
- 미매핑, 중복, 기존 값 충돌, 수업 없는 날이 실행 전에 드러난다.
- 날짜+교시 기준으로 셀을 선택하고 입력 후 값을 다시 확인한다.
- 특수 명령을 과목으로 선택하지 않는다.
- 주 단위 실패 시 저장하지 않고 정확한 원인을 보고한다.
- 재실행과 재개가 이미 일치한 셀을 중복 처리하지 않는다.
- 실제 개인정보가 테스트·문서·진단 자료에 포함되지 않는다.
- 사용자 설명서와 유지보수 문서가 실제 동작과 일치한다.

### 설계 주의

- 평가계획 SubjectPlan 스키마에 시간표를 억지로 넣지 않는다.

- HWPX 텍스트는 표 구조가 평탄화되므로 원본 위치가 불명확할 수 있다. PDF 원문과 결과 품질을 비교한다.

### 완료 기준

- 세 형식 중 실제 지원 가능한 경로가 동일한 TimetableSourceLesson 목록을 만든다.
- 잘못된 날짜와 중복 교시는 입력 화면 전에 차단된다.
- 사용자가 AI 결과를 직접 수정하고 확정할 수 있다.

## 17. 다음 개발자 시작점

가장 먼저 T1만 구현한다. UI나 브라우저 자동화를 동시에 시작하지 않는다.

권장 첫 작업 단위:

1. TimetableOptionKind와 NeisTimetableOption
2. 특수 명령을 우선 제외하는 메뉴 문자열 파서
3. TimetableTokenNormalizer
4. TimetableMappingRule과 충돌을 드러내는 Resolver
5. 위 네 항목의 xUnit 테스트

첫 작업이 끝나면 T1 체크리스트와 진행 기록을 갱신하고, 전체 테스트가 통과한 뒤 T2 또는 T4 중 하나를 시작한다. T2와 T4는 서로 독립적으로 진행할 수 있지만 T5는 둘 다 끝난 뒤 시작한다.
